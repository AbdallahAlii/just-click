JustClick AI — RAG System Guide

Prepared for team panel · August 2026

1. What is RAG?

RAG = Retrieval-Augmented Generation. Instead of asking an AI model to answer from its general knowledge (which can hallucinate or make up answers), we:

  1. Retrieve the most relevant paragraphs from the actual course material file
  2. Generate an answer using only those paragraphs

This keeps every answer grounded in the real material content — the AI cannot make things up.

2. The Two Models We Use

RoleModelRuns WhereWhy
Embedding (search)BAAI/bge-small-en-v1.5Locally on our server (CPU)Converts text into numbers (vectors) for meaning-based search
LLM (answers)deepseek-chatDeepSeek cloud APIReads retrieved text and writes human-quality answers

Why two models? The embedding model runs locally so we never send full documents to an external API. Only small text snippets go to DeepSeek when a student asks a question.

What is BAAI/bge-small-en-v1.5?

BAAI (Beijing Academy of AI) created this open-source embedding model. "bge-small" means it's lightweight (~130 MB) and runs fast on CPU without needing a GPU. It converts any text into a list of 384 numbers (a "vector") that captures the text's meaning.

What is DeepSeek?

DeepSeek is an AI company providing LLM API access (like OpenAI). We use their deepseek-chat model via an OpenAI-compatible API. It receives only the retrieved text snippets plus the student's question, and generates an answer. Requires an API key (DEEPSEEK_API_KEY).

3. What is an Embedding?

An embedding is a list of numbers (384 numbers in our case) representing the meaning of text:

TextVector (simplified)
"Python is a programming language"[0.12, -0.34, 0.56, …]
"A coding language called Python"[0.11, -0.35, 0.55, …] — very similar!
"The weather is sunny today"[0.89, 0.22, -0.41, …] — very different

Similar meanings → similar vectors. This is how we search by meaning instead of just keywords.

4. What is a Vector Database (ChromaDB)?

A vector database is specialized storage for searching by meaning. Regular PostgreSQL searches by exact text or keywords, but it cannot answer: "find the paragraph most similar to this question."

ChromaDB is NOT inside PostgreSQL. It stores data as files on disk at backend/instance/chroma_db/. It's a lightweight embedded database — no extra server process needed.

Why can't we just use PostgreSQL? PostgreSQL stores material metadata (title, type, file path, view counts). But to find "which paragraph of this 50-page PDF best answers the student's question," we need vector similarity search — that's what ChromaDB does.

5. How the System Works

Indexing (background, once per material)

1
Read the material file (decrypt if encrypted with Fernet)
2
Extract text from PDF / PPTX / PPT / DOCX
3
Split text into small chunks (~400 words each, with 80-word overlap)
4
Convert each chunk into a vector using the local BAAI model
5
Store chunks + vectors in ChromaDB
6
Record indexing status in PostgreSQL (chatbot_material_indexes table)

Answering (when student asks a question)

1
Student asks: "What is polymorphism?"
2
Convert the question to a vector (same BAAI model)
3
Search ChromaDB for the 5 most similar chunks from that specific material
4
Send those chunks + the question to DeepSeek: "Answer using only this context"
5
Return the answer to the student

6. Database Tables Used by RAG

TablePurpose
chatbot_material_indexesTracks indexing status per material (indexed / pending / failed, chunk count, file hash)
chatbot_index_jobsBackground job queue — worker picks pending jobs and processes them
chatbot_sessionsChat conversations (one per student per material)
chatbot_messagesIndividual messages (user questions + AI answers)

9. What is Seed Data and Why We Use It

Seeding means populating the database with demo/test data so the application has something to show. Our seed creates:

  • 1 university (Jamhuriya University)
  • Faculties, departments, semesters
  • Courses with chapters
  • ~100–180 demo materials (PDF, slides, docs, videos)
  • 1 admin user (jc_admin) and 1 demo student (C12222)
  • RBAC roles and permissions

The seed is idempotent — running it again will not create duplicates.

Seed Commands

cd backend && source .venv/bin/activate # Seed everything (recommended for fresh setup) flask --app cmcp seed all # Destructive reset — removes all demo data, then re-seed flask --app cmcp demo-reset --yes flask --app cmcp seed all # Index materials for AI chatbot after seeding python scripts/reindex_existing_materials.py python scripts/chatbot_index_worker.py --until-empty

12. Why Slides/DOC Can't Preview in Browser

PDF and Video can be previewed directly in the browser because all modern browsers have built-in PDF viewers and video players.

PPTX/PPT and DOCX cannot be reliably previewed in the browser because:

  • Browsers have no built-in PowerPoint or Word viewer
  • Converting them to viewable formats (like Google Docs Viewer) requires sending files to a third-party service, which conflicts with our file encryption and privacy requirements
  • JavaScript-based PPTX/DOCX renderers exist but are unreliable with complex formatting, fonts, and layouts

For these types, users are directed to the material detail page where they can download the file and open it in their desktop application.
